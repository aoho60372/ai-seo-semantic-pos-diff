# Анализ изменений SEO-позиций по кластерам

Workflow анализирует изменения органических позиций Google и Яндекса для
коммерческой семантики. Он отвечает на вопрос какие кластеры формируют падение или рост в конкретных зонах выдачи и
отличаются ли они от общего фона.

## Что делает workflow

- принимает один или два файла: `google.*` и/или `yandex.*`;
- обрабатывает CSV, TSV, XLS и XLSX;
- строит локальные semantic embeddings и кластеры запросов;
- считает переходы между позиционными зонами `1`, `2-3`, `4-5`, `6-10`, `11+`
  и `0`;
- находит кластеры, которые теряют или получают позиции заметно чаще общего
  фона;
- формирует отдельные отчёты для Google и Яндекса;
- использует облачную модель только для финального текстового объяснения. Исходные
  таблицы и дополнительные CSV в облако не передаются.

Все расчёты, embeddings, кластеризация и Excel-отчёты выполняются локально.

```text
semantic-pos-diff/

```

Папка с моделью находится рядом с папкой проекта, поэтому workflow остаётся
переносимым: он вычисляет путь относительно собственного расположения, а не
использует зашитый путь диска.

## Требования

- Windows 10/11;
- Python 3.11 или новее;
- для быстрой обработки больших файлов — NVIDIA GPU с CUDA;
- свободное место для модели, Python-зависимостей и временных embeddings;
- доступ к DeepSeek нужен только для финального текста в Hermes.

## Подготовка входных файлов

Поместите в `files/` один или оба файла:

```text
files/google.csv
files/yandex.xlsx
```

Имя файла обязательно определяет поисковик: допустимы только базовые имена
`google` и `yandex`. Если файлов нет, их больше двух или имя неверное, workflow
завершится с ошибкой.

Каждая таблица обязана содержать четыре колонки:

```text
query,freq,pos_cur,pos_prev
```

`0` в `pos_cur` или `pos_prev` означает отсутствие фразы в отслеживаемой
выдаче. Переход в `0` не считается обычной численной дельтой: это отдельное
событие исчезновения.

## Запуск через Hermes

Закройте Hermes, затем скопируйте slash-команду:

```powershell
$hermesSkills = Join-Path $env:LOCALAPPDATA "hermes\skills"
Copy-Item -Recurse ".\hermes_customizations\skills\sposdiff" $hermesSkills
```

Откройте папку проекта в Hermes, начните новый чат и выполните:

```text
/sposdiff
```

Hermes проверит `files/`, запустит workflow, безопасно прочитает UTF-8
`insights.md` и сформирует финальный ответ на русском языке. Инструкции для
модели внутри навыка написаны на английском.

## Результаты

Каждый запуск создаёт папку `outputs/position-diff-<дата-время>/`.

Главный файл — `position_dynamics.xlsx`:

- `Executive summary` — итог по поисковику;
- `Yandex flows` / `Google flows` — общая матрица переходов между зонами;
- `Yandex loss anomalies` / `Google loss anomalies` — аномальные падения по
  кластерам;
- `Yandex growth anomalies` / `Google growth anomalies` — аномальный рост;
- `Yandex clusters` / `Google clusters` — полная сводка кластеров;
- `Yandex phrases` / `Google phrases` — уровень отдельных фраз;

Также создаются CSV для машинной обработки, `insights.md` и `run.json`.

## Расшифровка листов и столбцов XLSX

Листы с префиксом `Yandex` и `Google` имеют одинаковую структуру. Если для
поисковой системы не было входного файла, её листы в отчёт не добавляются.

### Executive summary

Одна строка на поисковую систему — быстрый обзор результата.

| Столбец | Значение |
| --- | --- |
| `search_engine` | Поисковая система: `yandex` или `google`. |
| `phrases` | Число обработанных уникальных строк (фраз) в её исходном файле. |
| `freq_sum` | Сумма частотностей всех фраз. Это справочный показатель; на выявление аномалий и CTR-вес не влияет. |
| `appeared` | Число фраз с переходом `0 → позиция`: фраза появилась в отслеживаемой выдаче. |
| `disappeared` | Число фраз с переходом `позиция → 0`: фраза выпала из отслеживаемой выдачи. |
| `loss_anomalies` | Число строк с `problematic = yes` на листе падений. Это не число фраз, а число обнаруженных сочетаний «кластер + переход». |
| `growth_anomalies` | То же для роста. |
| `verdict` | Общая классификация: изменения похожи на равномерные либо есть заметные кластерные аномалии. |

### Yandex flows / Google flows

Матрица переходов. Строка — зона предыдущей позиции, столбец — зона текущей
позиции; ячейка — число фраз с таким переходом. Например, строка `1` и столбец
`2-3` означают, сколько фраз ушло с первого места на второе или третье.

| Столбец | Значение |
| --- | --- |
| `previous_position_band` | Зона позиции в прошлом сборе: `1`, `2-3`, `4-5`, `6-10`, `11+` или `0 (absent)`. |
| `1`, `2-3`, `4-5`, `6-10`, `11+`, `0 (absent)` | Зона позиции в текущем сборе. Значение ячейки — количество фраз, перешедших из зоны строки в зону столбца. `0 (absent)` означает отсутствие фразы в выдаче. |

Диагональ матрицы — фразы, оставшиеся в той же зоне. Это не обязательно та же
точная позиция: например, переход `2 → 3` остаётся внутри зоны `2-3`.

### Yandex global loss / Google global loss

Главный лист для поиска причины общего падения. Здесь каждый переход по всем
фразам агрегирован и ранжирован по оценённой потере CTR-видимости.

### Yandex global growth / Google global growth

Та же логика для общего роста. Значения `relative_ctr_impact` в этих двух листах
всегда положительны: направление задано названием листа.

| Столбец | Значение |
| --- | --- |
| `prev_band` | Позиционная зона прошлого сбора. |
| `cur_band` | Позиционная зона текущего сбора. |
| `phrases` | Количество фраз с данным переходом. |
| `relative_ctr_impact` | Сумма изменений модельного CTR по фразам. Единица измерения — процентные пункты CTR, сложенные между фразами; это индекс сравнительной важности, а не прогноз реальных кликов. |
| `share_of_direction_pct` | Доля этого перехода во всех потерях на листе `global loss` либо во всём росте на листе `global growth`. |

### Yandex growth contributions / Google growth contributions

Расшифровка того, какие кластеры создают конкретный общий переход. Например,
после выбора `prev_band = 1` и `cur_band = 2-3` можно увидеть вклад кластеров в
потерю `ТОП 1 → ТОП 2-3`. Это лист вкладов, а не список аномалий.

| Столбец | Значение |
| --- | --- |
| `prev_band` | Позиционная зона прошлого сбора. |
| `cur_band` | Позиционная зона текущего сбора. |
| `cluster` | Автоматически выделенный тематический кластер запросов. |
| `cluster_freq_sum` | Суммарная частотность всех фраз кластера. Справочный показатель: он не участвует в оценке CTR-эффекта и аномальности. |
| `phrases` | Количество фраз этого кластера с указанным переходом. |
| `relative_ctr_impact` | Вклад кластера в CTR-эффект именно этого перехода. |
| `transition_contribution_pct` | Доля кластера в суммарном CTR-эффекте выбранного перехода. Сумма значений всех кластеров для одной пары `prev_band → cur_band` равна примерно 100%. |

### Yandex loss anomalies / Google loss anomalies

### Yandex growth anomalies / Google growth anomalies

Поиск локальных отклонений. Одна строка означает: в данном кластере переход из
`source_band` в `target_band` происходит с определённой частотой и сравнивается
со средним фоном по всей семантике. Поэтому лист не отвечает на вопрос «какой
переход дал самый большой общий ущерб» — для этого есть `global loss`.

| Столбец | Значение |
| --- | --- |
| `cluster` | Автоматически выделенный тематический кластер. |
| `cluster_freq_sum` | Суммарная частотность всех фраз кластера. Справочный показатель: не влияет на определение аномалии. |
| `metric` | Технический идентификатор перехода, например `1_to_2_3`. Удобен для фильтрации; смысл читается по двум следующим столбцам. |
| `source_band` | Зона, из которой фразы вышли. |
| `target_band` | Зона, в которую фразы перешли. В падениях `11_plus` включает позиции 11+ и выпадение в `0`. |
| `phrases` | Общий размер кластера. |
| `eligible_phrases` | Число фраз кластера, которые находились в исходной зоне и могли совершить этот переход. Это знаменатель для доли. |
| `affected_phrases` | Сколько из `eligible_phrases` фактически совершили указанный переход. |
| `affected_rate_pct` | Доля затронутых фраз внутри кластера: `affected_phrases / eligible_phrases × 100`. |
| `global_rate_pct` | Такая же доля по всей семантике, без деления на кластеры: фоновая вероятность перехода. |
| `rate_lift` | Во сколько раз переход чаще в кластере, чем в общем фоне. Например, `1.8` означает в 1.8 раза чаще. |
| `excess_phrases` | Оценка числа затронутых фраз сверх ожидаемого на общем фоне: фактическое количество минус ожидаемое. |
| `relative_ctr_impact` | Полный CTR-эффект затронутых фраз в этой строке. Для листа падений это потеря, для роста — прирост; число выводится без знака. |
| `excess_relative_ctr_impact` | CTR-эффект сверх ожидаемого для такого размера кластера на среднем фоне. Отрицательное значение означает, что эффект ниже фонового ожидания. |
| `priority_score` | Приоритет локальной аномалии: положительная часть `excess_relative_ctr_impact`. Он ранжирует только кластерные отклонения и не заменяет общий рейтинг из `global loss` / `global growth`. |
| `dropouts_within_transition` | Только в листе падений: сколько затронутых фраз фактически перешло в `0`, то есть выпало из выдачи. В листе роста всегда `0`. |
| `problematic` | `yes`, если одновременно достаточно велика выборка и количество фраз, а частота перехода заметно выше общего фона; `no` — строка показана для сравнения, но формально не признана аномалией. |

#### Как читать CTR-эффект на листе падений

`relative_ctr_impact` — полный модельный эффект конкретной строки. Для каждой
из `affected_phrases` рассчитывается разница между CTR исходной и текущей
позиции, затем разницы складываются. Например, если в кластере 515 фраз
перешло из `2-3` в `6-10`, этот показатель — суммарная потеря модельной
кликабельности именно этих 515 фраз. Это не число реальных кликов и не
учитывает `freq`.

`excess_relative_ctr_impact` показывает только часть CTR-потери, которая
превышает нормальный фон для кластера такого размера. Ожидаемое количество
затронутых фраз рассчитывается как:

```text
eligible_phrases × global_rate_pct
```

Если в кластере 1 605 фраз находились в зоне `2-3`, а общий переход `2-3 →
6-10` по сайту происходит у 17.73% фраз, ожидаемое число переходов — около
285. Если фактически перешло 515, то примерно 230 фраз — сверх фонового
ожидания (`excess_phrases`). `excess_relative_ctr_impact` измеряет CTR-потерю,
которая соответствует этому избыточному отклонению.

Практическая трактовка:

- высокий `relative_ctr_impact`, но `excess_relative_ctr_impact` около нуля —
  кластер заметно участвует в общем падении, однако падает примерно так же,
  как весь сайт;
- высокий `excess_relative_ctr_impact` — кластер упал хуже общего фона и
  является кандидатом на отдельную диагностику;
- отрицательный или близкий к нулю `excess_relative_ctr_impact` — переход в
  этом кластере не сильнее среднего фонового движения.

`priority_score` равен положительной части `excess_relative_ctr_impact`.
Поэтому он ранжирует локальные отклонения, но не заменяет рейтинг общих потерь
на листе `global loss`.

### Yandex clusters / Google clusters

Сводка по каждому кластеру, без привязки к одному конкретному переходу.

| Столбец | Значение |
| --- | --- |
| `cluster` | Название автоматического тематического кластера. |
| `phrases` | Число фраз в кластере. |
| `freq_sum` | Суммарная частотность фраз кластера. Только справка, не фактор важности или аномальности. |
| `comparable_phrases` | Число фраз, для которых есть позиции в обоих сборах (`pos_prev > 0` и `pos_cur > 0`). Только для них рассчитывается `median_delta`. |
| `median_delta` | Медиана численной разницы `pos_prev − pos_cur` среди сопоставимых фраз. Положительное значение — рост позиций, отрицательное — падение, `0` — без изменения. Не учитывает появления и выпадения. |
| `improved`, `worsened`, `stable`, `appeared`, `disappeared` | Число фраз каждого события внутри кластера. |
| `improved_share_pct`, `worsened_share_pct`, `stable_share_pct`, `appeared_share_pct`, `disappeared_share_pct` | Доля соответствующего события от всех `phrases` кластера. |

### Yandex phrases / Google phrases

Построчный уровень. Этот лист используют после нахождения интересного кластера
или перехода, чтобы увидеть конкретные запросы.

| Столбец | Значение |
| --- | --- |
| `query` | Поисковая фраза из исходного файла. |
| `freq` | Исходная частотность фразы. Не участвует в расчёте приоритета. |
| `pos_cur` | Текущая позиция; `0` означает отсутствие в выдаче. |
| `pos_prev` | Позиция прошлого сбора; `0` означает отсутствие в выдаче. |
| `cluster_code` | Короткий код кластера, например `Cluster 048`. |
| `cluster` | Полное имя кластера с характерными словами. |
| `cluster_freq_sum` | Суммарная частотность всех фраз кластера. Справочный показатель, одинаковый для всех строк одного кластера. |
| `event` | Тип изменения: `improved`, `worsened`, `stable`, `appeared` или `disappeared`. |
| `delta` | `pos_prev − pos_cur` только для фраз, присутствующих в обоих сборах. Положительное число — рост, отрицательное — падение; для появлений и выпадений пусто. |
| `ctr_prev` | Значение модельной CTR-кривой для прошлой позиции. |
| `ctr_cur` | Значение модельной CTR-кривой для текущей позиции. |
| `relative_ctr_change` | `ctr_cur − ctr_prev`: положительное значение — прирост модельной видимости, отрицательное — потеря. Это не фактический CTR из Метрики. |
| `prev_band` | Позиционная зона прошлого сбора. |
| `cur_band` | Позиционная зона текущего сбора. |

## Как искать инсайты

1. Откройте `global loss` или `global growth` и определите переход с наибольшим
   `relative_ctr_impact`. Это главный вклад в общую потерю или рост видимости.
2. Откройте `flows`, чтобы визуально сверить этот переход с полной матрицей.
   Например, для падения с первого места на 2–3 смотрите строку `1` и столбец
   `2-3`.
3. В `loss contributions` или `growth contributions` отфильтруйте этот переход:
   так видно, распределён ли он между многими кластерами или сосредоточен в
   нескольких.
4. Затем в `loss anomalies` или `growth anomalies` включите фильтр
   `problematic = yes`, сортируйте по `priority_score` и сравнивайте
   `affected_rate_pct` с `global_rate_pct`. Это поиск отдельных кластеров,
   которые отклоняются от общего движения.
5. Учитывайте `dropouts_within_transition`: это число фраз, которые в рамках
   падения стали `0`.
6. Перейдите на лист фраз, отфильтруйте найденный кластер и нужные
   `prev_band` / `cur_band`, затем проверьте запросы и посадочные страницы.

`priority_score` — не прогноз трафика или дохода. Он задаёт очередь проверки
только среди кластерных отклонений: это дополнительная потеря или рост
модельной CTR-видимости сверх фонового ожидания для кластера. Общую важность
переходов всегда определяет `relative_ctr_impact` на листах `global loss` и
`global growth`.

`freq_sum` отображается только справочно и не участвует в расчёте аномалий.

## Ограничения

Workflow показывает позиционную динамику. Он не доказывает причины изменений,
не оценивает трафик или доход и не диагностирует санкции поисковых систем.
Для таких выводов нужны дополнительные данные: клики, показы, страницы,
индексация и журнал изменений сайта.
